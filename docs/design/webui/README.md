# 抖音下载 Web UI 设计稿

日期：2026-09-12。依据：`docs/analysis/2026-09-12-webui-design-brief.md`。

## 打开与体验

直接用浏览器打开本目录的 `index.html`，无需安装依赖或构建。也可以从仓库根目录运行：

```sh
python3 -m http.server 8769 --bind 127.0.0.1 --directory docs/design/webui
```

然后访问 `http://127.0.0.1:8769`。页面支持 `#download`、`#jobs`、`#history`、`#settings` 四个地址。

这是独立的设计交付，不是已经接入后端的 Web UI。页面不发起 API 请求，不读取真实配置、Cookie、下载文件或用户浏览器数据；演示数据只存在内存中，刷新恢复。封面是本地 SVG 示意图，作者与作品均为虚构。

推荐体验路径：

1. 下载页点击「试填示例链接」，提交两个任务，查看排队结果。
2. 任务中心取消任务，或重试失败任务；重试会保留原记录并新增任务。
3. 任务中心「再次下载」将链接带回输入框；「查看下载记录」进入按任务筛选的历史。
4. 历史默认每页 50 项，共 58 项，可切第二页；选择 8 项更方便预览分页。尝试作者、标题、类型、发布日期、任务 ID 与排序；点击「位置」显示完整路径。
5. 设置页查看配置与 Cookie 修复说明；侧栏底部可切换深浅外观。
6. 底部「原型状态预览」可切换空态、加载、请求失败、服务离线；设置页另有 Cookie 三态切换。此控制条仅用于评审，正式产品应移除。

演示中的初始运行任务每 2 秒增加一次计数直至完成；新建与重试任务保持排队，便于检查排队和取消状态。演示不会把模拟任务转成历史文件。暂停标签页或离开下载/任务页面时暂停计数；刷新可重新查看五态。

## 设计方向与取舍

一个个人下载工作台：打开页面即可粘贴，提交后立即看见任务。视觉重点是输入区和作品列表，去掉运营统计、营销区块和复杂导航。

采用冷静的墨蓝与雾蓝，不使用渐变、玻璃效果或大面积装饰。左侧固定单层导航让四种操作保持位置记忆；主区左对齐。大输入框像一个清晰的收件区，底部集中放置主操作，下载完成后视觉注意力自然转到历史。没有额外品牌名称，继续使用项目原名。

布局草案评审时舍弃了顶部汇总卡片：任务数与历史总量直接放在对应列表旁，避免把个人工具变成管理仪表盘。历史采用表格而非大封面卡片，保证能同时比较标题、作者、日期和路径入口。作者聚合为窄侧栏，在较窄窗口下移至表格后。

```text
┌──────────┬────────────────────────────────────────┐
│ 抖音下载 │ 工作台 / 当前页           设计预览标识 │
│          ├────────────────────────────────────────┤
│ 下载     │ 页面标题                               │
│ 任务中心 │                                        │
│ 下载历史 │ 下载：链接输入 → 识别 → 加入队列        │
│ 设置     │       最近任务                         │
│          │ 任务：状态筛选 → 计数 / 错误 / 操作     │
│          │ 历史：筛选 → 作品表格     常下载作者    │
│          │ 设置：只读偏好 → Cookie 修复指引        │
│ 外观切换 ├────────────────────────────────────────┤
│          │ 原型状态预览（仅评审）                 │
└──────────┴────────────────────────────────────────┘
```

字体采用系统字体：macOS 上使用系统无衬线与苹方，Windows 使用微软雅黑。无需联网加载字体。命令和完整路径使用系统等宽字体；作品标题保持普通正文。页面标题 28px/600，窄屏 24px；区块标题 16px/600；正文及输入控件 14px；桌面链接输入 16px；辅助信息 12px，短标签及作品 ID 10–11px。状态不能仅靠颜色表达。

主间距采用 4、8、12、16、20、24、32、40px。侧栏 216px，主区左右约 42px；小桌面侧栏 190px、主区边距 26px；720px 以下导航横排、边距 18px。表格在自身容器内横向滚动，不撑宽整个页面。

| 组件 | 规范 |
|---|---|
| 主按钮 | 雾蓝实底，6px 圆角；同一操作区只保留一个主按钮；不可提交时禁用 |
| 次按钮 | 表面底色、细边框；取消、重试、复制等保持明确文本 |

| 状态徽章 | 4px 圆角；图文短标签，不闪烁，不依靠红绿区分 |
| 任务卡片 | 8px 圆角；运行任务用左侧蓝线定位；计数使用等宽数字 |
| 进度条 | 3px 高，只表达作品处理比例；不表达网速或字节进度 |
| 历史表格 | 单层容器；封面 42×55px；标题最多约两行；路径放入弹窗避免挤压作品 |
| Toast | 底部居中，约 3.4 秒消失；用于操作结果，持久故障留在页面 |
| 路径弹窗 | 原生 dialog；关闭按钮、Escape、焦点约束；支持复制与手动选择 |
| 焦点 | 2px 清晰描边；表单均关联 label 或 accessible name |

动效仅用于运行计数对应的进度变化，400ms 宽度过渡。加载条只用于首次加载；系统减少动态效果时禁用动效。浅色沿用相同结构和语义。

## 接口与交互交接

### 提交下载

前端根据域名与路径进行轻量识别，不能据链接凭空显示作者或标题。短链接标记「提交后解析」，没有可提前展开的 API。原型支持提取分享文案中的多条 URL、去重和域名检查；作品路由识别只是提示，真实业务接受范围由后端验证。

收藏夹链接需在工程实现前核对真实格式和服务支持；当前原型不虚构收藏夹解析规则。`/collection/` 表示合集。短链、直播链接只识别类别，不声称解析或下载已成功。

真实接入使用 `POST /api/v1/download`，每条独立提交 `{url}`，服务响应成功后才建立真实任务。批量逐条请求至少间隔 2 秒，提交期间禁用重复提交。部分失败时保留失败行及原因，已接收行关联 job_id，不再次提交。响应丢失应先查询任务，避免盲目重试导致重复任务。

### 任务与轮询

`GET /api/v1/jobs` 返回近期集合，不代表永久记录。首次进入页面加载一次；存在 pending 或 running 任务时每 2 秒串行轮询，前次未返回不开始下一次。后台标签页暂停，返回时刷新一次。全部终态后停止。单任务详情可用 `GET /api/v1/jobs/{job_id}`。

真实轮询只更新数字、状态与进度，不重复替换整张卡片，不打断键盘焦点。处理量为 success + failed + skipped；total 未知时仅展示计数和「数量待获取」，不推算百分比、剩余秒数或下载速度。即使处理量等于 total，也必须等待后端 status 判断终态。

| 状态 | 界面 | 操作 |
|---|---|---|
| pending | 排队中；数量待获取 | 取消 |
| running | 计数、细进度条 | 取消 |
| success | 已完成；保留计数 | 重试、再次下载、历史 |
| failed | 失败；错误摘要和修复路径 | 重试、再次下载、历史 |
| cancelled | 已取消；保留已处理计数 | 重试、再次下载、历史 |

取消使用 `POST /api/v1/jobs/{id}/cancel`，响应前显示「正在取消」，不能先假定已取消。终态 409 表示状态已变化，应重新获取；404 解释为近期任务已不可用，给历史入口。

重试使用 `POST /api/v1/jobs/{id}/retry`，201 返回新的 job_id；原任务保留。它重试原 URL，不等于只重试失败作品。已下载内容能否跳过依赖服务配置。「再次下载」只把 URL 带回输入框，由用户再次提交。

首次请求失败展示可重试错误区；轮询中失败则保留最后一份任务数据，并标注「更新中断」和最后更新时间。不要把网络失败当下载失败。健康检查 `GET /api/v1/health` 只能证明服务可达，不能证明 Cookie 有效。

### 下载历史

`GET /api/v1/downloads`：默认 page=1、size=50。作者与标题搜索用显式字段选择，避免在不支持 OR 搜索的接口上错误地同时传 author 和 title。类型使用 video/gallery；job_id 精确筛选。条件变化回到第 1 页；真实查询需防抖并废弃过期响应。

**实际接口补充：** 已核对 `server/app.py`，date_from/date_to 按作品 create_time 过滤，所以界面使用「发布日期」。用户所选日期按明确时区取日初到日末，再转为 Unix 秒；原型固定 Asia/Shanghai。排序独立使用 download_time/create_time；切排序不改变日期过滤含义。

封面从 cover_urls 中选择可用地址，加载失败保留相同尺寸占位，不使行高跳动。原型使用本地虚构 SVG，并保留一组「暂无封面」状态。历史中的时间字段均为假数据，不是任务演示的下载结果。

路径使用服务端 file_path。浏览器不能直接打开服务机器的 Finder/文件管理器，也没有文件下载路由，因此入口叫「位置」，展示文本与复制动作。复制被浏览器限制时提示手动选择，不假报成功。

作者聚合调用 `GET /api/v1/downloads/authors?days=30&limit=20`，是近 30 天独立统计，不能用当前页 50 条结果冒充全量统计。原型按全部 58 条演示记录聚合。

### 设置与能力缺口

任务书希望少量配置可改，但 API 契约明确没有配置写入，甚至未提供配置读取、Cookie 检测端点。因此本稿采用只读样稿与显式「示例」标签，不放置假保存按钮，也不从 health 推断 Cookie 有效。

正式接入若没有新增接口，应保留配置文件说明，不显示虚假的当前生效值。若后续决定新增端点，再独立评审读写范围、校验、失败回滚及敏感字段处理。

Cookie 默认「未检测」。有效/失效的样稿由底部评审控件切换。失效指引使用任务书指定命令：

```sh
python -m tools.cookie_fetcher --config config.yml
```

本版不包含页内登录、Cookie 内容展示或上传。

## 工程实现边界

交付文件：`index.html`、`style.css`、`app.js`、`assets/cover-*.svg` 和本文。无 CDN、第三方字体、Node 构建链、框架或新增 Python 依赖。`app.js` 在对应操作旁标有真实接口接入注释，但没有执行 fetch。

正式实现时替换演示数据与计时器，移除原型状态控制条、演示标识、示例链接及虚构封面。保留布局、token、语义标签、错误提示和交互约定。服务返回的所有标题、作者、URL 与错误文本都应以文本节点输出，不能直接拼接未转义 HTML。
