# webui3：合并设计原型

2026-09-12。执行依据：[合并计划](../../analysis/2026-09-12-webui-merge-plan.md)。状态：Phase 1 离线原型已完成，等待用户视觉验收；Phase 2 真实接线未开始。

## 打开

浏览器直接打开 `index.html`，或在仓库根目录运行：

```sh
python3 -m http.server 8773 --bind 127.0.0.1 --directory docs/design
```

打开 `http://127.0.0.1:8773/webui3/`。同一服务可访问 `/webui/`、`/webui2/` 对照。四页地址为 `#download`、`#jobs`、`#history`、`#settings`。

全部为假数据，不读取配置、Cookie、真实作品或用户浏览器页面，不请求 API。原两版目录保持不动。默认深色，右上角可切浅色；外观单独存储在 `webui3-theme`，不改旧版外观偏好。没有新增构建链、框架或 Python 依赖。

## 评审操作

1. 下载页「混合多条」：5 条识别、1 条去重、4 个待提交；逐条模拟加入任务，间隔 2 秒。
2. 任务页：切五态筛选、取消、重试、再次下载和按任务查历史；重试创建新 ID，原记录保留。
3. 历史页：作者字段输入「机芯」得到 0 条，切标题得到 4 条；默认 50 条一页，共 58 条，切下一页或每页 8 条；点击位置弹出完整路径。
4. 底部先选「已有数据」，再点「请求失败/服务离线」：四页均显示横幅，内容仍可读。
5. 底部先选「空数据 / 首次加载」，再点「请求失败/服务离线」：四页显示整页错误态。重新加载恢复正常空页，不虚构下载记录。
6. 「Cookie 失效」：顶部出现设置入口，设置页出现命令 `python -m tools.cookie_fetcher --config config.yml`。

数据场景是评审开关，会替换当前内存中的任务与历史；不会操作任何真实数据。故障开关停止模拟轮询；正常模式恢复模拟进度。页面级内容判断按未过滤的任务/历史集合以及设置示例是否存在；正式接线应使用每个资源的请求状态与成功快照，区分成功空集合、从未请求成功和刷新失败。

## 视觉规范与接线约定

视觉 token 与组件沿用 [webui2 规范](../webui2/README.md#视觉规范)，最终以本目录 `style.css` 为准；本次没有重新设计颜色或导航。输入辅助文案与配置说明已按真实能力收紧。

真实接线依据合并计划 Phase 2：

- 搜索仅传 `author` 或 `title`；日期按 Asia/Shanghai 日初日末转 Unix 秒，并按 create_time 筛选。
- 后端 status 决定终态；不能从计数推测成功。总数未知时使用不定进度。
- 取消等待响应，409 重拉，404 给历史入口；重试保留旧任务、使用新的 job_id。
- 没有配置读写或 Cookie 检测端点，不展示假保存和假检测；health 只代表服务可达。
- 路径弹窗仅展示和复制服务端路径；浏览器不能据此打开服务器上的文件管理器。
- 首次请求与刷新分开；有数据时更新中断保留内容，最后成功时间按资源记录。

本原型仍沿用 webui2 的 `renderAll()` 模拟重绘与随机进度。它不证明正式轮询所要求的 DOM 稳定、焦点保持、串行请求、后端确认终态已经实现。Phase 2 必须改为真实状态驱动的局部更新，并对焦点、乱序响应和提交响应丢失单独测试。

桌面后续路线见 [macOS 与 Windows 复用边界](../../analysis/2026-09-12-desktop-delivery-plan.md)。本目录没有桌面桥、打包脚本或 DMG/EXE。
