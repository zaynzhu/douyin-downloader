# 抖音下载 Web UI 设计稿 · webui2（控制台卡片流）

日期：2026-09-12。依据：`docs/analysis/2026-09-12-webui-design-brief.md`。
本稿与同目录 `webui/` 相互独立，是同一任务书的另一套自由设计方向，供交叉对比。

## 设计读（Design Read）

把它读作：**自托管个人工具的「仪表控制台」**，单用户、高频、暗环境使用，语言是克制的工程工具感，不是后台管理模板，也不是营销页。三档拨盘：方差 4（规整网格，允许横带与窄侧栏破开）/ 动效 3（仅状态与进度动）/ 密度 6（日常 App 密度，列表是主角）。

和第一版的差异（刻意为之）：第一版是近白、浅灰、文字列表式的开放工作台；本版是深色、卡片化、控制台读数式的仪表工具。两版在信息架构上都服从任务书四页，但「第一眼气质」和组件形态完全错开，方便对比取舍。

## 打开方式

浏览器直接打开本目录 `index.html` 即可，或从仓库根目录跑：

```sh
python3 -m http.server 8770 --bind 127.0.0.1 --directory docs/design/webui2
```

然后访问 `http://127.0.0.1:8770`。支持 `#download`、`#jobs`、`#history`、`#settings` 四个地址。默认深色；右上角可切浅色。页面不发任何真实请求，演示数据只在内存中，刷新即恢复。

推荐体验路径：

1. 下载页：点「混合多条」往输入框塞 5 行（含一段分享文案、一条重复），看识别 chips 与去重提示；⌘/Ctrl+Enter 提交。
2. 任务中心：顶部 Tab 切「进行中」和「失败」；对失败任务点「重试」（新增任务、保留原记录）。
3. 下载历史：在「作者或标题」里输一个作者名，或切类型为「图文」；翻页默认 50/页，总量 58，可切第 2 页；点任意行「位置」看完整路径弹窗；展开底部「近 30 天下载最多作者」。
4. 设置页：用底部「原型状态预览」把 Cookie 切到「失效」，看修复指引；把任务状态切到「请求失败」或「服务离线」，回到任务中心看横幅。

| `--text` / `--muted` / `--faint` | `#e9edf2` / `#9aa4b0` / `#66717d` | `#1e2226` / `#5c666f` / `#87919b` | 正文/辅助/最弱 |
| `--accent` | `#4cc38a` | `#1f8a5b` | 主按钮、链接、进度 |

字体：系统无衬线栈（PingFang/YaHei 优先），无外部字体。`--font-mono` 栈用于 URL、job_id、计数、时间等读数。标题层级：页标题 21px、面板标题 14px、正文 14px、辅助 12–12.5px、读数与 URL 10.5–11.5px 等宽。

间距基于 4px 网格（4、8、12、14、16、18、20、28、40）。整页最大宽度 1120px，左右边距 32px。圆角体系单一：小件 6px、卡片/面板 10px、胶囊徽章与分段控件圆角 999px，不混用其他圆角。960px 以下输入区与说明上下排列，640px 以下顶栏换行、单列排布。

| 组件 | 规范 |
|---|---|
| 顶栏 | 64px 高、毛玻璃压底；左品牌（徽标+名称+「设计原型」标签），中四个文字导航，右侧服务/Cookie 胶囊+主题切换。选中导航：accent 文字 + 底部 2px 指示条 |
| 服务胶囊 | `服务未检查 / 服务正常 / 服务异常 / 服务离线` 四态，含最后联通时间；Cookie 失效时多出一个红色胶囊，点击跳设置页 |
| 主按钮 | accent 实底 + 深色文字，6px 圆角，`:active` 下沉 1px；主按钮内嵌数量徽标与 ⌘↵ 快捷键提示 |
| 幽灵按钮 | 描边 + 表面底，用于行内操作（取消/重试/再次下载/下载记录/位置）。危险动作用 `danger` 变体（红字红 hover） |
| 五态徽章 | 胶囊；语义色小圆点 + 文字，圆点不只靠颜色也靠文字区分；`running` 的圆点做 1.6s 呼吸脉冲 |
| 类型徽章 | 描边小方块（非胶囊），视频/图文/用户主页/合集/音乐/直播/短链接；识别不出时虚线描边「未知」 |
| 识别 chips | 下载页输入框下的逐行反馈：类型徽章 + 截断 URL + 状态标记（重复/非抖音/提交后解析）+「移除」 |
| 任务卡 | 头行：状态徽章 + 单色 job_id；主体：类型标题 + URL + 计数 + 3px 进度条 + 错误块 + 操作条；失败时错误块下直接给修复命令文与设置页链接 |
| 进度条 | 3px 高、accent 填充、400ms 宽度过渡，只表达「处理数/总数」；`total` 未知时不显示百分比，用不定态斜纹流光条 |
| 历史表格 | 全宽表格，表面底、细分隔线、表头压暗；封面 40×53 固定尺寸，加载失败原地换同尺寸「无封面」占位 |
| 分页 | 上一页/下一页/页码信息/每页 8|20|50；顶部作者聚合成可折叠 `<details>`，点开是一行内作者芯片 |

| 设置面板 | 三块：Cookie 状态（含失效修复命令块）、当前生效配置（标「示例快照」）、服务信息（地址/文档/健康检查） |
| Toast | 底部居中、最多存活约 3.4s，只用于操作结果；持续故障（离线/轮询中断）不走 Toast，走页内横幅 |
| 焦点与可达性 | `:focus-visible` 统一 2px accent 描边；跳转主内容链接；表单控件全部有关联 label；徽章用文字不独靠颜色 |
| 动效 | 只有三处：running 圆点脉冲、进度条宽度过渡、不定态流光；`prefers-reduced-motion` 下全部关掉 |

## 交互与轮询约定

- **提交**：多行输入，粘贴含分享文案的整段文字时提取所有 `http(s)` URL；仅保留抖音域名；重复链接默认按首现去重并在 chips 里标注，可在提交前逐条「移除」。确认后逐条 `POST /api/v1/download`，串行、每次间隔 ≥2 秒；部分失败保留对应行与原因，不清空整个输入框。
- **轮询**：存在 `pending` 或 `running` 任务时以 2s 间隔串行轮询 `GET /api/v1/jobs`（前次未返回不发起下一次）；页面不可见时暂停，回前台立即刷一次；全部进入终态后停轮询。轮询只更新数字、进度条宽度与徽章文字，不整卡重建，不打断焦点。
- **进度语义**：`total` 未返回前显示「总数 获取中」+ 不定态条；即使处理量等于 `total`，也必须等后端 `status` 变终态才改徽章。不估算剩余时间、不显示下载速度。
- **取消**：点「取消」立刻把按钮改成「正在取消…」并禁用；`POST /cancel` 返回后再改状态。409 表示已进入终态，重新拉取；404 解释为「任务已不在内存集合中」，给历史入口。
- **重试**：`POST /retry` 返回 201 新 `job_id`，原任务保留在列表。重试是「重投原 URL」，不是「只重试失败作品」，操作条旁固定一行小字说明。
- **网络故障**：首次加载失败显示可重试的错误区；轮询中失败保留最后一份任务数据，顶部横幅提示「请求失败 + 最后成功时间 + 重试按钮」。健康检查 `GET /api/v1/health` 只证明服务可达，不证明 Cookie 有效。
- **失败修复**：任务内错误块直接给出 `python -m tools.cookie_fetcher --config config.yml` 与跳设置页的链接，设置页有同一命令的复制块。
- **空态文案**：下载页空态用输入框占位与两个示例按钮引导；任务中心空态说明「任务只在内存，重启清空，已完成作品在历史里」；历史空态提示放宽筛选。

## 与 API 契约的对应关系

全部以任务书第 4 节为准接入；`app.js` 在对应操作旁留有注释锚点：

| 界面行为 | 接口 |
|---|---|
| 提交下载（逐条、间隔 2s、部分失败保留） | `POST /api/v1/download` |
| 任务列表首次加载 + running 时 2s 轮询 | `GET /api/v1/jobs` |
| 取消（先「正在取消」，响应后改终态） | `POST /api/v1/jobs/{id}/cancel` |
| 重试（新增任务、保留原记录） | `POST /api/v1/jobs/{id}/retry` |
| 历史列表/筛选/分页；`date_from/to` 按 `create_time`，界面文案用「发布日期」并按 Asia/Shanghai 取日初日末 | `GET /api/v1/downloads` |
| 近 30 天 Top 作者（独立聚合，不拿当前页结果冒充） | `GET /api/v1/downloads/authors?days=30&limit=20` |
| 服务正常性、设置页健康检查 | `GET /api/v1/health` |

契约里没有的能力一律没画假按钮：设置页不放假保存，配置标「示例快照」；Cookie 只在「失效」示意态给修复指引，不做页内登录；文件名「位置」用弹窗展示+复制，不假装能打开 Finder。

## 工程边界与验证

交付文件：`index.html`、`style.css`、`app.js`、`assets/cover-*.svg`（8 张本地虚构渐变封面）与本文。无 CDN、无外部字体、无构建链、无新增 Python 依赖。`prefers-reduced-motion` 已接入；深浅两套 token 已就绪。正式实现时替换演示数据与定时器、移除底部「原型状态预览」控制条与「设计原型」标签，保留布局、token、语义标签与交互约定。后端返回的所有标题/作者/URL/错误文本以文本节点输出，不拼未转义 HTML。

验证（本次原型自检）：

- `node --check app.js` 通过。
- 界面文件（index.html / style.css / app.js）无 `—`/`–`；范围数字在 README 中以「至」或 `N-M` 表达，界面文案以中文逗号、句号、冒号代替。
- 四页在 390×844 窄窗口下有显式媒体查询折叠（顶部换行、输入区上下排列、筛选单列），无横向滚动依赖。
- 浏览器实测（Chrome，macOS）：填入「混合多条」识别出 5 条、去重 1 条、可提交；提交后按 2 秒间隔逐条加入队列并出现在任务中心与下载页最近任务横带；运行中的计数与进度条持续更新直至终态。任务中心五态 Tab 计数正确，重试会新增任务并保留原失败记录。历史页默认 50/页、58 条、封面加载失败原地替换「无封面」占位；切换 Cookie 失效后设置页出现修复命令块、顶栏出现 Cookie 失效胶囊。
- 本轮只验证了离线原型，不代表真实下载服务、Cookie 链路或浏览器剪贴板授权分支已验收；Safari 实机、屏幕阅读器与真实接口联调留待实现阶段。
