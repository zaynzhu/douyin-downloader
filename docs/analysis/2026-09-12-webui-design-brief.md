# Web UI 设计任务书（2026-09-12）

> 交给设计师（人或模型）的**自包含**任务说明：读完本文即可开始设计，不需要访问代码仓库。
> 设计完成后，实现由工程侧完成；工程侧会先做一轮"可实现性评审"（对照第 4 节 API 契约）再动工。

## 1. 产品定位与硬约束

- 产品：`douyin-downloader` 的自托管 Web UI——抖音批量下载工具的浏览器操作界面
- 定位：**本地、自用、开源、免费**的个人工具；不是后台管理系统，不要企业级仪表盘的观感
- 语言：中文界面（技术名词保留英文）
- **绝对禁止**出现的元素：邀请码、会员、内测资格、License 校验、登录页、付费引导——这些与产品价值观冲突
- 单用户使用：没有多角色/权限体系，不需要导航层级超过 1 层
- 优先级：**简单、直观**。打开页面 5 秒内知道怎么用，比好看更重要

## 2. 用户与核心循环

用户是维护者本人（懂技术，用中文）。核心使用循环只有三步：

```text
粘贴一个抖音链接（视频/图文/主页/合集/收藏夹，自动识别类型）
  → 发起下载，看任务进度（进行中/成功/失败，失败的可以重试或取消）
  → 翻历史：按作者/日期/类型过滤，看已下载了什么，文件在哪
```

## 3. 信息架构：四页

### 页 1 · 下载（主页）

- 一个大的粘贴输入框（支持一次粘贴多条换行分隔）
- 粘贴后即时反馈识别出的链接类型（视频/图文/用户主页/合集/音乐/直播/短链自动展开）
- 发起按钮 → 提交后跳转或浮现任务卡片
- 空状态要友好：示例链接占位、首次使用提示

### 页 2 · 任务中心

- 任务列表：进行中（含轮询中的"实时感"）/ 成功 / 失败 / 已取消
- 每个任务卡片展示：URL（或识别出的类型+作者）、状态徽章、进度计数（总数/成功/失败/跳过）、时间、错误摘要
- 操作：取消（进行中）、重试（终态）、再次下载（复制 URL 回下载页）
- 状态徽章五态：`pending`（排队中）/ `running`（进行中）/ `success` / `failed` / `cancelled`

### 页 3 · 下载历史

- 表格/卡片流：作品封面（有 cover_urls）、标题、作者、类型（视频/图文）、发布时间、下载时间、文件路径
- 过滤：作者名/标题子串搜索、类型筛选、按任务（job_id）过滤、日期范围
- 分页（默认 50/页，总量显示）
- 附带一个小聚合：近 30 天下载量 Top 作者

### 页 4 · 设置

- 只读展示当前生效的关键配置 + 少量可改项：下载画质、并发数、Cookie 状态（有效/失效，附"重新获取 Cookie"的指引文案，本版本不支持页内登录）
- Cookie 失效时给出明确的修复指引文案（运行 `python -m tools.cookie_fetcher --config config.yml`）

## 4. API 契约（真实实现，设计数据态以此为准）

Base URL：`http://127.0.0.1:8000`（FastAPI 自带 `/docs` OpenAPI 页可交互体验）

### 提交下载

```text
POST /api/v1/download        body: {"url": "https://v.douyin.com/xxxx/"}
→ 200 {"job_id": "a1b2c3d4e5f6", "status": "pending", "url": "..."}
```

### 任务查询

```text
GET /api/v1/jobs/{job_id}
→ {"job_id": "...", "url": "...", "status": "running",
   "created_at": "2026-09-12T12:00:00Z", "started_at": "...", "finished_at": null,
   "total": 12, "success": 8, "failed": 1, "skipped": 3, "error": null}

GET /api/v1/jobs → {"jobs": [ 同上结构… ]}     # 近期任务，受 TTL/容量约束

POST /api/v1/jobs/{job_id}/cancel   → 200 任务当前状态；终态任务 409；未知 404
POST /api/v1/jobs/{job_id}/retry    → 201 {"job_id": "新id", "status": "pending", "url": "..."}；进行中 409
```

**重要**：没有推送通道（无 WebSocket/SSE）。前端用**轮询**拿进度（建议 running 态 2s 间隔、有任务在跑时才轮询）。设计要考虑轮询的视觉语义：数字跳动、状态徽章过渡，而不是骨架屏死等。

### 历史查询

```text
GET /api/v1/downloads?page=1&size=50&author=xxx&title=xxx&aweme_type=video&job_id=xxx&date_from=0&date_to=9999999999&sort=download_time
→ {"total": 128, "page": 1, "size": 50, "items": [
     {"aweme_id": "7346971177114611826", "aweme_type": "video",
      "title": "作品标题", "author_id": "...", "author_name": "作者名",
      "author_sec_uid": "MS4w...", "create_time": 1740441600,
      "download_time": 1760000000, "file_path": "Downloaded/作者/post/2026-02-25_标题_7346.../xxx.mp4",
      "cover_urls": ["https://..."], "job_id": "a1b2c3d4e5f6"} ]}

GET /api/v1/downloads/authors?days=30&limit=20
→ {"authors": [{"sec_uid": "...", "author_name": "作者名", "download_count": 42}]}
```

`date_from`/`date_to` 是 unix 秒。`sort` 可选 `download_time` / `create_time`。

### 健康检查

```text
GET /api/v1/health → {"status": "ok"}
```

**不存在的端点**（设计不要依赖）：登录/注销、实时进度流、作品删除、配置写入、上传。

## 5. 设计自由度

- **刻意不提供任何参考截图或既有界面模仿对象**：希望你在第 2-3 节的需求边界内自由构思，不被某个现存产品的形态锚定
- 需求的全部边界 = 第 3 节四页信息架构 + 第 4 节 API 契约 + 第 6 节技术约束；布局密度、视觉语言、组件形态完全由你决定
- 唯一的风格约束在第 8 节（克制的工具感、避免通用 AI 风）

## 6. 技术约束

- 实现将是**纯静态前端**（HTML/CSS/原生 JS 或极轻方案）由 FastAPI 托管，无 Node 构建链、无前端框架依赖进后端仓库
- 设计时请产出可直接转成静态实现的方案；若你的交付物本身就是 HTML 原型，用占位假数据即可，fetch 调用点留注释
- 浏览器目标：现代 Chrome/Safari；桌面优先，窄窗口可用即可（无移动端完美要求）
- 深色/浅色：任选一种做精，另一种保可用（推荐优先深色，下载工具用户多在暗环境使用）

## 7. 期望交付物（按优先级）

1. **HTML/CSS 静态原型**（最重要）：四页各一个可打开的 html（或单文件切页），含假数据与所有状态（空态/加载/五态任务/失败态/分页）
2. **设计规范**：配色 token（主色/语义色/背景层次）、字体层级、间距体系、组件清单（按钮/输入框/徽章/卡片/表格/Toast）
3. **交互说明**：轮询反馈方式、状态过渡、错误呈现原则、空状态文案

## 8. 风格方向（供参考，可推翻）

- 关键词：克制的工具感——不是营销页，是高频使用的仪表工具
- 避免通用 AI 风：无渐变横幅、无玻璃拟态、无居中 hero 大标题
- 参考 res-downloader 的产品哲学："打开就会用"——列表即主界面，动作在 5 秒内可达
