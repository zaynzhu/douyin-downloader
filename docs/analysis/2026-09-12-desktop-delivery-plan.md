# 桌面交付方向：macOS DMG，随后 Windows EXE

2026-09-12。状态：纳入规划，尚未选择壳技术、创建桌面工程或生成安装包。

## 当前决策

用户在 Web UI 合并任务中明确提出后续考虑桌面版，先 macOS DMG，再 Windows EXE。本方向替代 [旧评估](2026-09-12-desktop-evaluation.md) 的默认“不做”结论；旧评估保留作历史背景。当前交付仍是 webui3 离线原型，按 [合并计划](2026-09-12-webui-merge-plan.md) 完成视觉验收后再接真实服务。

桌面分发不意味着需要账号、邀请码、会员、License 或付费体系。这些不属于本项目目标。也不恢复不存在的上游桌面仓库同步流程。

## 现在应保持的复用边界

建议后续采用同一套正式静态前端、同一套 Python 下载服务，加一层薄的桌面宿主。宿主负责窗口、进程生命周期和系统能力，不复制下载规则。这里只确定职责，不把某个框架或打包器写成既定选择。

| 部分 | 共享内容 | 平台差异 |
|---|---|---|
| 界面 | 四页布局、任务状态、过滤、日期、错误文案 | 原生标题栏留白、快捷键提示、系统外观 |
| 服务 | DownloadService、任务接口、历史查询、限速 | 宿主启动/结束进程、服务端口、运行参数 |
| 文件位置 | 后端返回完整路径，页面显示文本 | 浏览器复制路径；本地桌面可增加 Finder / 资源管理器定位 |
| 配置 | Python 端校验和持久化规则 | 系统目录选择器、可写应用数据目录 |
| Cookie | 状态和错误保持诚实，凭证不进前端存储 | 桌面后续需独立设计获取与存储流程，不能直接把 CLI 文案当成免环境产品 |
| 构建 | 正式静态资源与后端版本配对 | macOS 与 Windows 各自构建、安装、验证 |

Phase 2 应集中实现 API 客户端，用相对 `/api/v1` 地址，避免页面组件写死 127.0.0.1:8000。下载后端应同源提供前端；桌面宿主只注入一次启动配置。不要现在堆通用插件体系、系统平台分支或假桌面按钮。

文件位置的桌面增强要按能力开放：只有本机服务且宿主确认能力存在，才显示「在 Finder / 资源管理器中显示」。远程服务器路径继续展示与复制，不能当作客户端本地路径。宿主按记录 ID 向后端取受控路径，不接受页面任意命令、任意文件路径或无限制系统桥。

## macOS 第一阶段的最小验证

先确定用户希望的是独立窗口，还是一个双击启动浏览器的入口。DMG 是交付容器，单有 DMG 并不代表具备独立桌面体验。本轮不擅自将其中一种写成已经获准的实现。

在真正开发桌面版时，用最小实验验证以下链路，再决定壳和打包工具：

1. 从 Finder 启动，用户机器不依赖开发仓库、系统 Python、终端 shell 或开发机绝对路径。
2. 宿主启动内置 Python 服务，等待就绪后加载共享 UI；启动失败显示原因和重试入口，不永久白屏。
3. 监听仅绑定回环地址；端口冲突能处理。若开放本地 HTTP 写接口，设计每次启动的身份校验与请求来源边界，不能因为地址是 localhost 就认为任何页面都可信。
4. 窗口关闭与退出策略明确；进程由宿主跟踪，退出停止自己启动的进程，不能按模糊名称误杀其他实例。首版不承诺重启后续传或恢复内存任务。
5. 配置、数据库、Cookie、日志在明确的用户可写目录；下载位置由用户选择。应用包与 DMG 内不保存可变数据。已有 CLI 数据导入另作明确、可回退的流程，不能首次启动就静默扫描迁移。
6. 用中文、空格、长路径和下载目录不可写场景验证。明确目标芯片架构，分别构建和实机验证，不把开发机成功等同于全部 Mac 可用。
7. 将 app 打成 DMG 后，在无开发依赖的测试环境走挂载、安装、首次启动、下载、退出、重开、替换升级流程。对外分发前完成签名、公证与下载后首次打开验证；未完成时如实标注测试包状态。

实现前的本仓库证据：`server/app.py` 已委托 `core.download_service.DownloadService`；`pyproject.toml` 将 server/browser/transcribe 分成可选依赖。桌面打包需要明确收集哪些依赖与本地二进制，尤其是浏览器获取 Cookie、ffmpeg 和可选转写，不能假定所有功能都会自然进入安装包。

## Windows 后续阶段

macOS 最小交付稳定后，再沿同一静态前端/API 契约实现 Windows 宿主与打包。EXE 的交付形式（安装器或便携程序）届时确定，不用后缀代替产品决策。

Windows 必须在 Windows 构建与实机测试：进程结束方式、端口占用、路径分隔、中文用户名、长路径、目录权限、内置运行时、资源管理器定位、安装升级和卸载后的数据保留。共享后端修复留在本仓库，不维护复制出来的第二份业务核心。

暂不提前加入自动更新、托盘常驻、剪贴板监听、全局快捷键或跨设备同步。需要时分别立项；桌面发行不改变“本地、自用、开源、免费”的定位。
