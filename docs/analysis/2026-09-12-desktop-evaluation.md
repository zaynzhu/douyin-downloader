# 桌面端（Desktop App）评估结论（2026-09-12）

> 路线图长期 #4 的交付物。读者：未来纠结"要不要做桌面端"的任何人/模型——读完本文就不需要重新推导一遍。
> 结论先行：**维持"不做"**，触发条件与翻案路径见 §3-4。

## 1. 评估范围

"桌面端"指独立的桌面应用形态（Electron / Tauri / 打包可执行文件），区别于"CLI + 浏览器访问 Web UI"。

## 2. 为什么默认不做（四层论证）

### 2.1 形态重复

桌面端的本质 = REST API + Web UI + 一个 WebView 壳。Web UI（长期 #1）完成后，桌面端不再提供新能力，只是换一个启动入口：从"终端跑 `--serve` + 开浏览器"变成"双击图标"。

### 2.2 成本-收益不对称（基于"用户=维护者本人"的事实）

| 一次性成本 | 持续维护税 |
|---|---|
| 壳工程：打包、自动更新、macOS 签名公证 | 每次依赖变化（playwright / imageio-ffmpeg pin）都要重新构建发布 |
| **Python sidecar 进程编排**：spawn / 健康检查 / 重启 / 端口协商 | 跨平台构建矩阵（amd64 / arm64 × macOS / Win / Linux） |
| 发布流水线（GitHub Releases 多平台 artifact） | 壳与核心两套版本节奏需保持同步 |

收益侧：省掉一次终端命令。对本项目的实际用户（维护者本人），收益≈0。

### 2.3 技术栈的结构性成本

核心是 Python。Go 系项目（res-downloader 用 Go+Wails）做桌面端是单二进制、天然轻；Python 应用做桌面壳必然是"壳 + Python 侧车进程"双进程架构——上游 Douzy 正是如此，也因此长出了 SSE 透传、license 校验、data-dir migration、崩溃恢复等一整层桌面独有代码（见上游 AGENTS.md 的 intentional divergences 清单）。这层复杂度在 CLI 仓里已经全部剔除过一次。

### 2.4 文化土壤论（最关键）

桌面分发是**分发给别人用**的形态。一旦开始分发，就会顺理成章地需要身份、授权、更新体系——上游的邀请码 / 内测资格 / License 校验正是顺着这条路长出来的。本 fork 的立身之本是"本地、自用、开源、免费"（README 关于本 Fork），没有分发需求，就不应该培育这个土壤。

## 3. 翻案触发条件

满足任一条即重开评估：

- **条件 A**：真实出现"给不装 Python 环境的人用"的需求（家人/朋友想用但不会配环境）
- **条件 B**：需要桌面级原生能力（系统托盘常驻、全局快捷键、剪贴板监听下载）且浏览器形态确实做不到
- **条件 C**：Web UI 实际使用 1-2 个月后，确认浏览器形态存在硬伤（例如误关标签页、无常驻感）

## 4. 真做时的路线排序（最廉价优先）

```text
第一优先：PyInstaller / cx_Freeze 把 CLI 打成单可执行文件
          + 启动即 --serve 并自动打开系统浏览器
          → 一个图标双击即用；零壳工程，复用 100% 现有代码
          参考：TikTokDownloader 的 GitHub Actions 自动构建流水线（cx_Freeze）
第二优先：Tauri + 复用 Web UI 前端 + Python sidecar
          仅当第一优先无法满足原生需求（托盘/菜单）时升级
不考虑：  Electron——~100MB 壳、Node 工具链、内存占用，
          对本项目没有任何它独有而 Tauri 没有的能力
```

## 5. 参考项目对照

| 项目 | 桌面形态 | 与本项目的可比性 |
|---|---|---|
| 上游 Douzy | Electron + Python sidecar，闭源内测分发 | 反面教材：展示的是"分发化"路线的完整成本（license/SSE/迁移层） |
| res-downloader | Go + Wails 单二进制 | 技术栈不同（Go 天生适合单二进制），路线不可迁移 |
| TikTokDownloader | cx_Freeze 打包 CLI + GitHub Actions 产线 | **正面参考**：触发条件出现时第一优先方案的现成模板 |
| F2 | 无桌面端，纯库 + CLI | 印证"非分发场景根本不需要桌面形态" |

## 6. 结论

维持路线图默认结论：**不做桌面端**。本文档即长期 #4 的完成交付物；若 §3 任一条件被触发，按 §4 排序重开评估并更新本文。
